# Аудит исходников и отладка

Дата: 10 ноября 2026. Объект: предоставленные `api.py` (1315 байт) и `utils.py` (3194 байта).
Перед реализацией изучен текст [урока VPf11](https://university.zerocoder.ru/pl/teach/control/lesson/view?id=345508163&editMode=0), включая исправления Flask, перенос на Go, перечень маршрутов, Docker и критерии домашнего задания.
Видеозаписи не просматривались; использован развёрнутый текст урока. Никакие формы/ответы в учебной системе не отправлялись.

Исходники сохранены байт-в-байт в `originals/`; SHA-256 и первичные ошибки разбора — в `originals/checksums.json`.
Это статический аудит и воспроизводимые регрессионные проверки, не заявление о полном внешнем penetration test.

## Блокирующие ошибки запуска

Оба файла содержат буквальные теги `<code ...>`, скопированные со страницы урока. После удаления только тегов файлы также не компилируются.
Для `api.py` AST сообщает ошибку закрывающей скобки на строке 12; для очищенного `utils.py` — отсутствующий отступ после определения функции на строках 29–31.
В `api.py` также испорчены вызов `sqlite3.conn@ct`, f-строка SQL, отступ return и закрывающие скобки jsonify.
В `utils.py` два определения `store_password`; второе находится в повреждённом HTML-фрагменте с отступом.
Сервис в предоставленном виде не запускается, поэтому исходный HTTP baseline получить невозможно.

## Восстановленный контракт

Локальный `api.py` заканчивается строкой `active = []`. Реализации `/activate/{id}`, `/slow`, `/wrong` восстановлены по тексту урока, а не найдены в исходном файле.
Путь `/adduser` взят из исправленного примера урока; буквальный `/adducer` сохранён как совместимый alias.
`/wrong` предсказуемо возвращает учебную ошибку 500; намеренно аварийный код в сервер не переносился.
Логика `is_admin` и `long_running_task` добавлена по уроку, в локальном utils.py этих функций не было.

## Отличия от примера урока

Урок упоминает `before_first_request`; актуальный Flask использует фабрику приложения с явной инициализацией до запуска.
Запуск через Waitress без debug. Парольные хеши хранятся в SQLite вместо текстового файла.
Неограниченное создание потоков заменено лимитом двух задач; 503 при занятости описан в OpenAPI.
В Go завершение по сигналу закрывает HTTP и отменяет работу. Активность остаётся в памяти процесса, что явно отражено в документации.
Нет неподтверждённых обещаний ускорения Go: сравнительный benchmark не проводился.
